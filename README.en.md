# norsk-lov-rag

**Interactive demo:** [norsk-lov-rag.azurewebsites.net](https://norsk-lov-rag.azurewebsites.net). Ask a question about Norwegian tax law and try the system yourself.

Questions and answers about Norwegian law, with a source for every claim. The system is a retrieval-augmented generation (RAG) system for Norwegian legal text, evaluated on tax law.

[Norsk versjon](README.md)

> **Important:** The answers are generated by a language model and may be wrong. They are not legal or tax advice. The law text is a fixed extract and may have changed. The project is not affiliated with the Norwegian Tax Administration (Skatteetaten), Lovdata or any other public body.

## What it does

A user asks a question in Norwegian, in bokmål or nynorsk. The system finds the relevant provisions in Norwegian acts and regulations and answers in Norwegian. Every sentence of the answer cites the provision it rests on, for example `[skatteloven § 6-44]`. When the law text does not answer the question, the system says so instead of guessing.

The project has these parts:

- a parser for the structure of Lovdata's documents, from chapter down to letter, and a graph of cross-references such as "jf. § 5-1";
- a comparison of lexical search, multilingual and Norwegian embedding models, hybrid search and reranking, on the tax corpus and on all current acts and regulations;
- answers from a local Norwegian model and from a model on a free API tier, with citation checks and abstention when the text gives no answer;
- a test set of 344 questions and an evaluation with confidence intervals.

The method works on any Norwegian act or regulation. Tax law is the domain used for the evaluation and the examples.

## Results

Retrieval is measured on the 198 test questions that have an answer in the corpus. Numbers in brackets are 95 percent confidence intervals.

| System | Corpus | Recall@10 | MRR | nDCG@10 |
|---|---|--:|--:|--:|
| BM25 | tax | 0.879 | 0.783 | 0.781 [0.73, 0.82] |
| bge-m3 | tax | 0.934 | 0.856 | 0.853 [0.82, 0.89] |
| Hybrid with reranking | tax | 0.957 | 0.948 | 0.931 [0.90, 0.96] |
| Hybrid with reranking | all acts and regulations | 0.927 | 0.913 | 0.892 [0.86, 0.92] |

Reranking gives the largest gain. Chunks that follow the structure of the law are clearly better than fixed-length windows. All numbers and comparisons are in the [validation report](docs/valideringsrapport.md) (Norwegian).

The answers are measured on all 240 questions in the test set. Correctness is judged by a language model against the reference answers, on the 198 questions that have an answer.

| Generator and retrieval | Correctness | Citation recall | Support | Correct refusals | False refusals |
|---|--:|--:|--:|--:|--:|
| NorMistral 7B, BM25 | 0.631 [0.57, 0.69] | 0.056 | 0.405 | 0.000 | 0.010 |
| NorMistral 7B, hybrid with reranking | 0.641 [0.58, 0.70] | 0.068 | 0.574 | 0.024 | 0.020 |
| Gemma 4 31B, BM25 | 0.821 [0.77, 0.87] | 0.768 | 0.988 | 0.976 | 0.157 |
| Gemma 4 31B, hybrid with reranking | 0.917 [0.88, 0.95] | 0.869 | 0.984 | 0.976 | 0.051 |

Gemma with hybrid retrieval and reranking gives the best answers. It usually cites the right section, its citations support its claims, and it refuses when the law text has no answer. The local NorMistral writes fluent Norwegian, but rarely cites in the fixed format and almost never refuses.

The test set was written and reviewed by language models, and the answers were judged by a language model.

## Getting started

The project needs Python 3.11 or newer.

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -e ".[dev,embed]"
```

Each stage is one command. Model answers are cached under `data/`, so the stages can be run again on the same machine without new calls.

```bash
norsk-lov-rag corpus                      # download Lovdata's datasets and build the tables
norsk-lov-rag references                  # find cross-references and build the graph
norsk-lov-rag index                       # build chunks and embeddings
norsk-lov-rag retrieve-eval --split test  # evaluate retrieval
norsk-lov-rag generate --split test       # generate answers
norsk-lov-rag judge --split test          # judge the answers
norsk-lov-rag report --split test         # compute the measures
norsk-lov-rag figures                     # build the figures
norsk-lov-rag demo-export                 # build the files for the demo
streamlit run app/Home.py                 # start the demo
```

The frozen test set is in `testsett/`. The command `norsk-lov-rag testset` builds it again and needs keys for the free APIs.

Keys for the free APIs are read from a `.env` file that is not part of the repository: `GROQ_API_KEY` for Groq and `GEMINI_API_KEY` for the Gemini API. The local model runs in [Ollama](https://ollama.com). See `configs/ollama/normistral.Modelfile` for how to set it up.
